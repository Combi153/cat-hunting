## 링크 미리보기 소개 문구 변경 (2026-11-18)

사용자가 기존 ‘평범한 손짓일까’ 표현을 어색하다고 느껴 대안을 검토한 뒤 ‘누가 몰래 정답을 보고 있을까요? 시험 감독이 되어 45초 안에 부정행위를 모두 찾아내세요.’를 선택했다. 일반 페이지 설명·Open Graph·X 소개에 같은 문구를 사용한다. 제목·대표 이미지·게임 내 문구와 결과별 기본 공유 메시지는 유지한다.

## 기록의 범위

이 문서는 확인 가능한 대화의 요청·피드백과 커밋을 연결한 요약이다. 직접 확인할 수 없는 초기 대화는 재구성하지 않고 ‘저장소 이력’으로 표시한다. 요청과 구현 판단을 구분하며, 표의 완료는 구현 반영을 의미한다. 재미를 객관적으로 입증했다는 뜻은 아니다.

## 결과·일시정지 버튼 정리 (2026-11-18)

사용자가 결과의 작은 ‘링크 복사’ 버튼을 없애고, 일시정지의 소리 버튼 자리에 ‘시험 그만두기’를 놓도록 요청했다. 결과는 ‘친구에게 공유하기’ 하나로 기본 공유·미지원 시 자동 복사를 제공한다. 일시정지에는 계속하기와 그만두기 두 버튼을 두며 기존 그만두기 확인 절차를 유지한다. 음소거 설정은 로비에서 조절한다.

## 시험 표시 잘림 수정과 데스크톱 세로 구성 (2026-11-18)

사용자가 중앙 정렬 후에도 짧은 화면에서 ‘시험 중’ 표시가 사라진다고 지적했다. 이전 변경에서 남겨 둔 카메라 잘림을 수정해 표시의 테두리부터 감독관 발끝까지 담는다. 이어 데스크톱의 오른쪽 안내 영역을 없애고 모바일과 같은 비율을 요청해, 데스크톱은 최대 540×960px의 9:16 중앙 세로 화면과 하단 안내·조작으로 통일했다. 결과·다시 보기도 같은 구성을 따른다. 짧은 휴대폰 가로 배치는 조작 공간을 위해 유지하며 HUD를 오른쪽으로 옮겨 교실 높이와 44px 학생 터치 영역을 확보한다.

## 직접 운영하는 학원 홍보 표시 (2026-11-18)

사용자가 생각하는 공간은 직접 운영하는 학원이며 대가를 받고 게재하는 광고가 아니라고 설명하고 ‘홍보’ 표기를 제안했다. 로비·결과 배너 상단의 ‘광고’를 ‘홍보’로 바꾸고 접근성 이름도 함께 맞췄다. 배너 이미지·연결 주소·배치는 유지한다.

## 교실 뒤편 시험 중 표시 중앙 정렬 (2026-11-18)

사용자가 뒤편의 ‘시험 중’ 표시를 교실 중앙에 맞추도록 요청했다. 사물함 중심에 맞춰져 있던 글자와 테두리의 x 좌표를 -0.65에서 0으로 옮겨 가운데 학생 열·교탁과 같은 중심선에 배치했다. 뒤쪽 벽의 높이와 표시 크기는 유지한다.

## 제작자 연락처 (2026-11-18)

공개 연락처에 대한 안내 후 사용자가 제작자명 ‘후추’와 `hodooo153@gmail.com`을 제공했다. 로비 맨 아래 배너 다음에 제작자와 이메일 링크를 표시한다. 함께 입력한 ‘svg’는 오타라고 확인해 별도 SVG는 만들지 않았다. 메일 발송·새 분석 이벤트는 추가하지 않는다.

## 사용자가 추구한 경험

최초 요청은 게임 개발·기획·디자인 관점에서 루브릭을 만들고, 당시 상태를 항목별 1점으로 놓아 각 5점 기준까지 개선하며 직접 플레이하고 적절히 커밋하라는 것이었다. 이후 피드백에서는 다음 의도가 반복됐다.

- 학생을 잘 볼 수 있고 손쉽게 조작하는 모바일 화면.
- 메뉴나 설명을 읽어 정답을 찾기보다 행동을 살피고 판단하는 재미.
- 감독관의 이동, 커튼 조작, 오인당한 학생의 감정처럼 원인과 결과가 연결되는 장면.
- 첫 판의 부담은 낮추고, 뒤로 갈수록 일정한 폭으로 판가름하기 어려워지는 시험(최신 D20 피드백).
- 짧게 도전하고 다시 해볼 수 있는 진행.

## 생각하는 공간 배너 연결 (2026-11-18)

사용자가 제공한 `thinkplace-banner-kit`으로 기존 카페 배너를 제거·교체하도록 요청했다. 최초 인스타그램 목적지를 후속 요청에서 생각하는 공간 홈페이지로 바꿨다. 로비·결과의 기존 위치에 3:1 원본 비율과 최대 320px 너비를 적용하고 전체 클릭으로 새 탭을 연다. 유입 출처는 `utm_source=cat_hunting`, 위치는 `utm_content=lobby/result`로 구분한다. 기존 카페 이미지와 전용 스타일은 삭제했다. ## 추가 조작·규칙 문구 승인 (2026-11-18)

사용자가 앞서 제안한 세 가지를 모두 승인했다. 일시정지 화면에 생명 감소와 민원 발생 조건 두 문장을 추가하고, 학생 선택·복귀·관찰 종료의 ‘탭’ 표현을 ‘누르다’로 통일했다. 마지막 단계 결과의 ‘다섯 시험 돌아보기’는 실제 단계 선택 이동에 맞춰 ‘다른 단계 다시 하기’로 바꿨다. 앞선 첫 화면 문구 기록의 미반영 제안은 이 승인으로 구현 범위에 포함됐다. 게임 규칙·난이도·정답 비공개는 유지한다.

## 성공·실패 결과 공유 (2026-11-18)

사용자가 결과에서 친구에게 링크를 보낼 수 있는 방법을 조사한 뒤, 우선 ‘친구에게 공유하기’ 버튼과 기본 공유·링크 복사 구현을 요청했다. 결과 버튼에서 공유 선택창을 열고, Web Share API 지원 여부에 따라 기본 공유를 제공한다. 링크 복사는 항상 제공하며 클립보드 실패 시 직접 선택 가능한 URL로 보완한다. 성공·실패·전체 통과 문구와 공개 게임 시작 주소만 공유하며, 기존 진행·저장·분석 의미는 유지한다. 카카오톡 전용 공유와 인스타그램용 이미지 생성은 이번에 승인된 구현 범위가 아니다. [운영과 검증 범위](../engineering/sharing-and-deployment.md#결과-화면의-친구-공유)

사용자 후속 요청: 휴대폰에서 앱·카카오톡 대화 상대가 보이는 기본 공유창을 바로 열기를 원했다. 결과의 ‘친구에게 공유하기’에서 `navigator.share`를 직접 호출하도록 중간 선택창을 제거했다. 결과에 별도 ‘링크 복사’를 유지하고 미지원·오류만 복사 안내창으로 대체한다. 취소하면 추가 UI 없이 결과에 머문다. 기본 공유 목록의 앱·대화 상대 구성은 OS가 결정한다.

후속 인앱 브라우저 피드백: 사용자는 모바일 Chrome에서는 기본 공유가 열리지만 카카오톡 인앱 브라우저에서는 링크 복사 안내가 표시된다고 보고했다(OS는 미확인). 이 환경에서는 별도 모달 없이 바로 복사하고 끝나기를 요청했다. 공유 미지원·오류와 별도 링크 복사 모두 바로 복사를 시도하고, 성공하면 3초 알림만 표시한다. 자동 복사도 차단된 경우에만 주소 선택창을 제공한다. 공유 취소는 복사하지 않는다.

## 첫 화면 문구 개선 (2026-11-18)

사용자가 ‘학생을 탭하다’라는 표현의 어색함과 게임 설명의 충분함을 지적해 제시한 새 문구를 승인했다. 로비 목표에 종이 울리기 전이라는 제한을 넣고, ‘학생을 눌러 가까이에서 살펴보기 → 부정행위를 발견하면 신고 → 손을 든 학생 요청 듣기’로 정리했다. 다른 화면의 설명 보완은 검토 요청이며 이번 구현은 승인된 로비 문구에 한정한다. 생명 감소 조건·민원의 의미와 조작 표현 통일 등은 후속 제안으로 구분한다.

## 방문자·진행 분석 추가 (2026-11-18)

사용자가 방문자 수와 어디에서 막히고 어느 단계에서 탈락하는지 확인하고 싶다고 요청했다. GA4 방문 분석과 단계 시작/종료/재도전/명시적 그만두기, 실패 원인별 누적 수를 수집한다. 사용자가 제공한 측정 ID `G-TV3RS6L0MR`을 Vercel Production 환경에 설정했다. 탭 숨김은 일시 중단과 구별할 수 없으므로 확정 이탈로 기록하지 않는다. 설정 방법·이벤트·검증 결과는 [플레이 분석](../engineering/analytics.md)에 기록했다.

## 변경된 요구를 해석할 때 주의할 점

깜빡임은 난이도 아이디어의 예시로 다시 언급됐지만, 재도입하기로 확정한 요청은 없었다. 명시적인 제거 요청과 현재 구현을 유지한다. 단계별 힌트 제거는 기본 조작 안내나 학생의 불편함 경고까지 없애라는 뜻으로 확대하지 않았다.

‘적발 수 비공개’는 누적 수와 전체 목표 수를 숨기는 결정이다. 적발 성공 반응과 학생의 퇴실까지 감추는 규칙은 아니다. 학생 번호도 모든 위치에서 금지한 것이 아니라 학생을 가리는 큰 번호표를 제거했다.

45초 첫 시험의 범인 수, 노출 시간, 요청 시각 같은 수치는 사용자 요구를 구현하기 위한 개발 판단이다. 사용자가 숫자를 각각 지정한 것은 아니다. 상세 수치는 [게임 기획](../product/game-design.md)에만 관리한다.

현재의 에이전트 분업은 새 학생 에셋 제작에 대한 명시적 요청을 수행한 사례다. 모든 후속 작업을 여러 에이전트에 맡기라는 별도 요구로 해석하지 않는다.
