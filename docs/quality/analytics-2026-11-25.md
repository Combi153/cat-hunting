이번에 다시 조회한 **11월 18~19일**의 기존 1단계 `level_end` 집계는 다음과 같다. 초기 당일 중간 스냅샷과 조회 범위가 다르다.

완료 판 성공률 = `56 / (271 + 149 + 56)` = **11.8%**. 사용자별 첫 도전 성공률이 아니며 재도전과 당시 여러 규칙·빌드가 섞여 있다.

### 튜토리얼 도입 이후의 관측

11월 20일 도입한 1단계는 시간제한 없이 쪽지 적발·수험표 오인·답안지 전달을 연습한다. 시험의 `level_start`/`level_end` 대신 별도 튜토리얼 이벤트를 보낸다.

| 기간 | 시작 이벤트 / 총 사용자 | 완료 이벤트 / 총 사용자 | 완료/시작 사용자 집계 비율 |
| --- | ---: | ---: | ---: |
| 11월 18~24일 전체(튜토리얼은 20일 이후) | 42 / 32명 | 33 / 25명 | 25 / 32 = **78.1%** |
| 11월 21~24일 | 23 / 18명 | 17 / 14명 | 14 / 18 = **77.8%** |

전체 기간의 완료/시작 **이벤트** 비율은 `33 / 42 = 78.6%`다. README는 **사용자 집계 비율 78.1%**를 사용한다. 이는 서로 다른 이벤트의 총 사용자 수를 나눈 것으로, 동일 사용자의 시작→완료 순서를 검증한 퍼널이나 개별 연습의 완료율이 아니다.

11월 21~24일 대시보드의 `level_start` 중 `exam_2`·`start_source=advance`는 **14회·활성 사용자 13명**이었다. 같은 기간 튜토리얼 완료 총 사용자 14명과는 측정항목이 다르고 사용자도 연결하지 않았으므로 13/14를 전환율로 계산하지 않았다. 기존 단계 해제·재방문도 구분하지 않았다.

| 기간 | 성공 | 생명 소진 | 미검거 | 완료 합계 | 완료 판 성공률 |

| 11월 18~19일 | 14 | 22 | 35 | 71 | 14 / 71 = **19.7%** |
| 11월 21~24일 | 7 | 7 | 8 | 22 | 7 / 22 = **31.8%** |

완료 판 성공률에 높은 값이 관측됐지만, 소표본이고 유입 규모·구성·재도전·난이도·카메라·다시 보기·손과 소품 변경이 함께 영향을 줄 수 있다. 이번 표는 규칙·빌드별 분리도 하지 않았다. **튜토리얼이 2단계 성공률을 높였다는 인과효과나 통계적 유의성을 입증한 결과로 사용하지 않는다.**

기존 1단계 시험 성공률 11.8%와 튜토리얼 완료 사용자 집계 비율 78.1%도 목표·이벤트·분모가 달라 개선 폭으로 뺄 수 없다. 첫 단계 전환을 돕기 위한 설계와 도입 후 관측을 구분해 소개한다.

## 다음에 확인할 지표

1. **첫 단계 전환:** 같은 사용자의 `tutorial_start → tutorial_complete → level_start(exam_2)`를 순서와 기간을 정해 연결하고 첫 방문·재방문·빌드를 분리한다.
2. **학습 후 첫 시험:** 튜토리얼을 마친 사용자의 첫 `exam_2` 결과와 실패 사유를 확인한다. 현재 `attempt_number`는 새로고침 때 초기화되므로 생애 첫 도전으로 쓰지 않는다.
3. **다시 보기 후 재도전:** `previous_review`와 배포 버전별로 같은 단계 시작·종료를 비교한다. 다시 보기를 선택하는 사람의 성향 차이를 고려한다.
4. **소품 가독성:** 최신 `exam_2` 이후를 충분히 수집하고, 실제 휴대폰에서 처음 보는 사람의 관찰과 구별을 함께 확인한다.

이번 작업은 문서와 데이터 조회다. 게임 테스트를 새로 수행한 결과가 아니며, 기존 자동 검사나 개발자 플레이를 신규 이용자의 성공률로 대체하지 않았다.
