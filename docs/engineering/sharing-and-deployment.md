## 결과 화면의 친구 공유

2026-11-18: 로비·성공·시간 초과·생명 소진·전체 통과 결과에 ‘공유하고 3회 더 받기’를 제공한다. `src/share.js`가 해당 버튼에서 중간 선택창 없이 기본 공유를 호출하고, 공유 미지원·오류 시에는 바로 클립보드 복사를 시도한다. 성공 시 재도전 3회를 추가하고 3초 알림을 표시하며, 자동 복사까지 실패한 경우에만 `<dialog>`로 직접 선택 가능한 주소를 보여준다. 기본 공유는 로비·결과 버튼 클릭 핸들러에서 바로 `navigator.share({ title, text, url })`를 호출한다. `navigator.share` 미지원 또는 `canShare` 거절·예외 시 즉시 링크를 복사한다. 앱 이름을 감지해 기본 공유를 일괄 차단하지 않는다. 결과의 작은 링크 복사 버튼은 제거했으며 공유 버튼 하나로 제공한다. 카카오 SDK·새 의존성·외부 서버 설정은 필요하지 않다.

- 공유 URL은 `index.html`의 canonical 주소를 읽는다. 개발·미리보기 주소, 쿼리·해시와 저장 데이터는 전달하지 않는다. 친구는 게임 시작 화면으로 들어가며 보낸 사람의 진행 상태를 가져오지 않는다.
- 결과에 맞는 짧은 문구를 사용한다. 링크 복사는 문구 없이 URL만 복사한다. 기본 공유에서 어떤 앱이 표시되고 어떤 내용이 전달되는지는 OS·브라우저·대상 앱에 달려 있다.
- 취소하면 추가 UI 없이 현재 화면에 머물고 복사를 강제하지 않는다. 공유 오류는 링크 복사로 대체한다. 복사 권한 거절·API 미지원 시 선택 가능한 읽기 전용 주소를 표시한다. 처리 중 중복 클릭을 막고 닫힌 창의 비동기 응답은 새 창을 덮어쓰지 않는다. 공유를 시작한 화면을 떠나면 알림을 지우고 늦게 도착한 공유·복사 응답도 무시한다.
- 공유 완료 응답은 친구에게 전달 완료가 아니라 OS 응답 `resolved`로만 분석한다. 누름·취소·오류·자동 복사 성공·수동 복사 안내를 구분하며 기존 저장과 플레이 이벤트의 의미는 유지한다.
- 카카오톡 전용 버튼과 인스타그램용 결과 이미지·자동 링크 스티커는 구현하지 않았다. 실기기 앱 전환·전송·미리보기는 별도 검증 대상이다.

공식 동작 근거 확인: 2026-11-18, [W3C Web Share API](https://www.w3.org/TR/web-share/). 자동 테스트의 공유 성공·취소·오류는 API 대역이며 실제 앱 전송의 증거가 아니다. 로컬 HTTP 휴대폰 접속은 보안 컨텍스트 제한으로 공유·클립보드 API가 없을 수 있으므로 실기기 기본 공유는 공개 HTTPS 주소에서 확인한다.

## 변경 후 확인

1. `npm run build`가 끝난 `dist/index.html`에 제목·소개·이미지 절대 URL이 있는지 확인한다.
2. 대상 팀·프로젝트·브랜치와 커밋을 확인하고 정상 Git 푸시로 반영한다.
3. 자동 배포가 READY인지, 공개 별칭이 그 커밋을 가리키는지 확인한다.
4. 공개 HTML을 JavaScript 없이 읽고 이미지가 HTTP 200과 JPEG MIME으로 응답하는지 확인한다.
5. 실제 카카오톡 카드 검증은 별도다. 아직 실행하지 않았다면 완료로 기록하지 않는다.

읽기 전용 확인 예시:

```sh
curl -fsSL -A 'facebookexternalhit/1.1;kakaotalk-scrap/1.0' https://cat-hunting.vercel.app/
curl -fsSI https://cat-hunting.vercel.app/art/exam-keyart.jpg
```

도메인을 바꾸면 canonical, `og:url`, OG/X 이미지 URL, 이 문서와 README의 공개 링크를 함께 변경한다. 대표 이미지 자체를 교체할 때는 이미지 URL의 버전도 고려한다.
